## P3 — cleanup

### 22. Двойное экранирование в текстовой части письма

**Файл:** `resources/views/emails/plain-text.blade.php`

**Сделано — тема письма.** `replacePlaceholders` получил параметр
`bool $escape = true`, `renderSubject` передаёт `escape: false`. Было
«Заявка от Иванов &amp; Партнёры», стало «Заявка от Иванов & Партнёры».
HTML-тело не тронуто. Снятие `e()` с темы не открывает инъекцию заголовков:
`e()` не трогает переводы строк, их кодирует Symfony Mailer.

Тест `test_replaces_placeholders_and_escapes_values` переименован в
`test_replaces_placeholders_in_subject_without_escaping` и перевёрнут — он
утверждал `&lt;b&gt;Bob&lt;/b&gt;` **в теме**, то есть закреплял дефект как
ожидаемое. Покрытие экранирования вынесено в новый
`test_html_body_still_escapes_values`; проверено мутацией.

**Осталось — текстовая часть.**

**Симптом:** значение экранируется дважды и попадает в `text/plain` с
сущностями. Проверено на реальном выводе (значение `Иванов & Партнёры`):

```
TEXT (рендерер) : Иванов &amp; Партнёры        ← e() внутри replacePlaceholders
BLADE (в письме): Иванов &amp;amp; Партнёры    ← {{ }} экранирует повторно
```

**Трасса:** `renderBodyText` зовёт `replacePlaceholders` с `escape: true`
(дефолт), затем `emails/plain-text.blade.php` содержит `{{ $textBody }}` и
экранирует повторно: `&` → `&amp;` → `&amp;amp;`.

**Проявляется** на любых данных со спецсимволами — амперсанд, кавычки,
апостроф в фамилии. В отличие от закрытых #8/#9/#14 виден в реальных письмах:
затрагивает и админские, и пользовательские (`SendFormSubmissionEmails:57-59,
76-78`), и предпросмотр в админке (`EditForm.php:91-92, 152-154`).

**Фикс:** `renderBodyText` передаёт `escape: false` (параметр уже есть после
фикса темы), а шаблон переводится на `{!! $textBody !!}` — это часть
`text/plain`, HTML там не исполняется. Обойтись без view нельзя: `Content`
принимает сырую строку только для HTML (`htmlString`), для текста — лишь имя
view.

**Тест:** нужен кейс на сам blade-шаблон, а не только на рендерер — сейчас
`test_renders_files_list_in_body` проверяет вывод `renderBodyText`, где
двойного экранирования ещё нет; оно возникает уже при рендере view.

## Проверено — не баг

- **Опциональный `select` с плейсхолдером отправляется штатно.**
  `FormRulesBuilder::optionValues()` выбрасывает пустые значения из
  `Rule::in()`, а в state лежит `''` — выглядит так, будто `nullable` +
  `in:` обязаны ронять отправку. Не роняют: Laravel пропускает
  неимплицитные правила для пустой строки
  (`Validator::presentOrRuleIsImplicit`). Обе ветки — optional проходит,
  required падает — закреплены в `PublicFormTest::
test_select_placeholder_passes_when_optional_and_blocks_when_required`.
