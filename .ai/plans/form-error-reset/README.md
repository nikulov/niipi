# Ошибки валидации публичной формы не гаснут по вводу

## Задача

После неудачного сабмита красное сообщение под полем висит до следующего
нажатия «Отправить» — даже когда значение уже исправлено. Заметнее всего на
телефоне: маска сама подставляет верный формат, а ошибка «Укажите телефон в
формате +7 (999) 123-45-67» остаётся. Надо, чтобы ошибка снималась по вводу,
как было до апгрейда Livewire.

Отложено 2026-09-03 решением владельца: разобрано, но не делаем.

## Разбор

1. **`wire:model` в Livewire 3 — deferred.** Запрос уходит только на действие
   (`submit`). Модификаторов нет ни у одного поля
   (`resources/views/components/form/fields/*.blade.php`). В Livewire 2
   `wire:model` был живым — отсюда «раньше работало»: коммит `98b1252`
   («removed model defer») писался под v2, апгрейд на v3 перевернул поведение
   молча.
2. **Ошибки переживают запросы.** `SupportValidation::dehydrate()` кладёт их в
   memo `errors`, `hydrate()` восстанавливает
   (`vendor/livewire/livewire/src/Features/SupportValidation/SupportValidation.php:12-42`).
   Поэтому «просто отправить запрос» мало: пока не позван `resetValidation()`
   или новый `validate()`, сообщение вернётся из снапшота.
3. **Телефон молчит гарантированно.** Маска пишет значение через
   `$wire.set(model, value, false)` (`resources/js/app.js:234`) — третий
   аргумент означает «локально, без запроса». Так и задумано (см.
   [../../patterns/livewire-public-form.md](../../patterns/livewire-public-form.md)),
   но значит, что телефон не доезжает до сервера до самого сабмита.

## План фикса

1. `PublicForm` — хук `updated(string $property)` → `$this->resetValidation($property)`.
   Livewire передаёт полный путь (`data.phone`,
   `SupportLifecycleHooks:75`), так что сброс точечный: соседние ошибки
   остаются на месте.
2. `phoneMask.push()` в `resources/js/app.js` — локальный `set(..., false)`
   оставить, добавить `$wire.$commit()`, когда номер набран целиком (11 цифр).
   Один запрос за номер, и сообщение гаснет ровно в момент, когда формат стал
   верным; на неполном номере ошибка честно висит.
3. Тест в `PublicFormTest`: сабмит с кривым телефоном → ошибка, затем
   `set('data.phone', '+7 (452) 354-32-53')` → `assertHasNoErrors('data.phone')`.
4. Дописать в `patterns/livewire-public-form.md`, что ошибки живут в снапшоте
   и снимаются только `resetValidation`.

## Открытый вопрос

Делать только телефон или заодно повесить `wire:model.blur` на остальные поля,
чтобы ошибка снималась по уходу из поля везде. Цена — по запросу на каждый
blur; выгода — единое поведение формы. Решения пока нет.

## Границы

- Правится `resources/js/app.js` → нужна пересборка ассетов, её запускает
  владелец.
- Серверные правила валидации не трогаем: `FormRulesBuilder` закрыт багом #43.
