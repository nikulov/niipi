# Закреплённые проекты в блоке «Проекты»

**Цель.** Блок `projects-block` подтягивал проекты только автоматически.
Нужна возможность выбрать в админке конкретные проекты: они идут первыми,
остальные места добираются автоподбором как раньше. Ничего не выбрано —
поведение прежнее.

## Что сделано (2026-08-05)

- `ProjectsBlock` — `Select::make('projectIds')`, multiple + searchable,
  опции из всех проектов по алфавиту. Порядок в блоке = порядок добавления
  в поле (состояние Filament-мультиселекта хранит выбор в порядке клика).
- `ProjectsQuery::byIds(array $ids)` — опубликованные проекты в порядке
  переданных id; неопубликованные и несуществующие id молча выпадают.
- `ProjectsQuery::list()` — пятый аргумент расширен с `?int $excludeId` до
  `int|array|null $excludeIds` (`whereNotIn`). Единственный вызов с этим
  аргументом — `RelatedThematicRenderer`, передаёт int, менять не пришлось.
  `NewsQuery` намеренно оставлен со старой сигнатурой.
- `ProjectsBlockRenderer` — закреплённые (обрезка по `limit`) + автодобор на
  остаток с исключением закреплённых id.
- Тесты: 4 сценария в `ProjectsBlockRendererTest` (пустой выбор, закрепление
  без дублей, черновик из выбора выпадает, перебор режется по `limit`) и
  2 в `ProjectsQueryTest` (`byIds`, множественный exclude).

## Решения

- **Перебор режется по `limit`.** Выбрали 6 при количестве 4 — покажет
  первые 4. Размер сетки предсказуем.
- **Неопубликованные из выбора выпадают,** место занимает автоподбор.
  Карточка не может увести на 404.
- **`quantity` → `limit` без чтения старого ключа.** Поле в Filament
  называлось `quantity`, а рендерер читал `limit` — значение из админки не
  доезжало, блок всегда показывал 4. Поле переименовано; старые записи со
  `quantity` в JSON остаются на дефолтных 4, пока редактор не пересохранит
  блок. Решение пользователя, осознанное.
