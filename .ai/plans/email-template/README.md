# Брендовый шаблон письма

## Задача

Свёрстан `resources/views/emails/email-template.blade.php` — обёртка письма по
макету: шапка-картинка, белая карточка с датой и телом, серый футер с
контактами, соцсетями и юридическим текстом. Подключена к письмам по заявкам
форм — и клиентскому, и админскому.

Коммиты: `fd3be48` (шаблон + экшены в секциях писем),
`7ebb25d` (поиск адреса, блокировка тумблера, диагностика).

## Решения по вёрстке

- **Шапка — одна картинка с запечённым логотипом**, вставлена `<img>`, а не
  фоном. Word-движок Outlook фоновых картинок не рисует, а `<img>` рисует, —
  поэтому шапка видна везде и ghost-таблица с синей плашкой не нужна.
  Ширина показа 588px = 600 карточки минус рамка по 6px; атрибут `width` обязан
  совпадать с ней, Outlook читает только его и игнорирует `max-width`.
- **Ассеты писем — `public/images/email/`, мимо Vite.** Хэш в имени меняется
  при каждой сборке, а письмо уже ушло со старой ссылкой. Пути строятся через
  `asset()`, то есть завязаны на `APP_URL`.
- **Тело шаблон не оформляет.** Приветствие, текст и подпись — всё это тело, и
  приходит оно со своими стилями из админки. Шаблон печатает `{!! $bodyHtml !!}`
  как есть, задавая только отступ и базовую типографику, которую наследуют теги
  без собственных стилей.
- **Стили только инлайн, в `<style>` — только `@media`.** Часть клиентов режет
  `<style>` (приложение Gmail с не-Google аккаунтом). Медиазапрос один — ≤600px,
  ужимает отступы карточки и футера и складывает телефон с почтой в столбик.
- **Рамка карточки — вложенность, а не паддинг.** Внешняя таблица красится в
  `#f6f4f4`, её ячейка даёт 6px отступа, внутри белая таблица с контентом.
  Паддинг на самой `<table>` не работает: под `border-collapse: collapse` он
  обнуляется по спецификации, а Outlook игнорирует его в любом случае.
- **Ширины: обёртка 800px, карточка 600px.** Волны (`wavy_bg.jpg`) — фон
  таблицы-обёртки, единственный фон в письме.
- **Шрифты** — `'Century Gothic', 'Carlito', Arial, Helvetica, sans-serif`,
  как на сайте. Вебфонты в почте не грузим.
- `$table` и `$image` в шапке шаблона — сбросы, которые лечат артефакты Outlook
  (`mso-table-lspace/rspace`) и синюю рамку вокруг картинок-ссылок (`border:0`).
  Выглядят мусором, но убирать их нельзя.

## Переменные шаблона

Все с дефолтами — шаблон рендерится и без данных: `$preheader`, `$date`,
`$body` / `$slot`, `$phone`, `$email`, `$siteUrl`, `$address`, `$policyUrl`,
`$legal`, `$socials`.

## Как письмо собирается

`FormEmailTemplateRenderer` (`app/Services/Forms/`):

- `renderLetterHtml()` — боевой путь: markdown из админки → HTML с подстановкой
  плейсхолдеров → обёртка в шаблон. Дата в карточке берётся из `created_at`
  заявки, а не из `now()`: очередь может дойти до письма сильно позже.
- `renderPreviewHtml()` — предпросмотр и тестовая отправка: markdown → HTML без
  подстановки, плейсхолдеры `{{ field.* }}` остаются видимыми, чтобы админ видел,
  где что окажется. Заявка для этого не нужна вообще.

Экшены предпросмотра и тестовой отправки — `FormMailActions`, привязаны к
секциям писем в `FormForm` и читают шаблон из текущего состояния формы.
Предпросмотр рисуется в `<iframe srcdoc>`: письмо — целый документ, вставленный
в страницу он дрался бы стилями с панелью.

## Отправка писем по заявкам

`SendFormSubmissionEmails`:

- **Адрес клиента** ищется по порядку: `data['email']`, `data['user_email']`,
  затем значение первого включённого поля формы с `type = 'email'` — поле могут
  назвать как угодно, тип надёжнее имени.
- **Плечо, которому некуда слать, больше не молчит.** Включён тумблер, а адреса
  нет — причина уходит в `error_message` заявки и в `Log::warning`, статус
  становится `Failed`, а не `Sent`. Раньше система рапортовала об успехе там,
  где клиент ничего не получал.
- **Тумблер «письмо пользователю» блокируется**, если у формы нет включённого
  поля типа Email: серый, выключенный, с подсказкой, плюс правило валидации на
  случай сохранения в обход (`FormForm::hasEmailField()`).

## Хвосты

- [ ] **Юридический футер написан от лица письма клиенту**, а шаблон общий с
      админским: «Вы получили это письмо в ответ на Ваше обращение… не требует
      ответа» + политика ПД. Админу это неверно от первого до последнего слова.
      Нужны разные тексты или `$legal` из места вызова.
- [ ] **Нет `Reply-To`.** В письме клиенту написано «просто ответьте на это
      письмо» — ответ уйдёт на `MAIL_FROM_ADDRESS` (`post@niipigrad.ru`). В
      админском письме `Reply-To` на адрес заявителя тоже нет.
- [ ] **Вложения теряются молча** — `buildFormUserAttachments()` отфильтровывает
      файлы, которых нет на диске, без следа в логах.
- [ ] Проверка в реальных клиентах (Outlook, Gmail, тёмная тема) — не делалась.
- [ ] Ключ `panel.no_submissions_for_preview` больше не используется.
- [ ] Dev-роут `/_preview/email` закомментирован в `routes/web.php` —
      раскомментировать, если снова понадобится править вёрстку.
