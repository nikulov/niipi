# Вёрстка письма по макету

## Задача

Сверстать `resources/views/emails/email-template.blade.php` (сейчас пустой) —
брендовую обёртку письма по макету: шапка с фото и логотипом, белая карточка
с приветствием и телом, серый футер с юридическим текстом, ссылками и
соцсетями.

Скоуп — **только вёрстка + превью**. Подключение к `TemplatedFormSubmissionMail` /
`UserFormSubmissionMail` / `AdminFormSubmissionMail` — отдельной задачей, после
того как макет посмотрят вживую.

## Решения

- **Шапка — одна картинка с запечённым логотипом**, вставлена `<img>`, а не
  фоном. Word-движок Outlook фоновых картинок не рисует, а `<img>` рисует, —
  поэтому шапка видна везде и ghost-таблица с синей плашкой из шаблона убрана.
  Ассеты писем лежат в `public/images/email/` и не проходят через Vite: хэш в
  имени меняется при каждой сборке, а письмо уже ушло со старой ссылкой.
- **Тело письма шаблон не оформляет.** Приветствие «УВАЖАЕМЫЙ» с именем,
  текст и подпись — всё это тело, и приходит оно уже со стилями: их задают
  в админке. Шаблон печатает `{!! $bodyHtml !!}` как есть, в обёртке только
  отступ сверху и базовая типографика (шрифт, кегль, интерлиньяж, цвет),
  которую наследуют теги без своих стилей.
- **Наезд карточки на шапку** держится на `margin-top: -40px` у обёртки
  карточки. Gmail и Outlook отрицательные отступы вырезают — там карточка
  просто встаёт под картинкой, ничего не ломается. Если наезд нужен во всех
  клиентах, верхнюю кромку карточки надо запекать в саму картинку шапки.
- **Стили только инлайн, в `<style>` — только `@media`.** Часть клиентов режет
  `<style>` (приложение Gmail с не-Google аккаунтом), поэтому всё оформление
  живёт в атрибутах, а в теге остаются два медиазапроса: ≤800px убирает боковые
  стенки со 100px до 16px, ≤600px ужимает отступы карточки и футера.
- **Шрифты** — `'Century Gothic', 'Carlito', Arial, Helvetica, sans-serif`
  (как на сайте, с системным фолбэком; вебфонты в почте не грузим).
- **Ширины: обёртка 800px, колонка контента 600px.** Разницу в 200px дают
  боковые «стенки» — паддинг ячейки `.side`, который медиазапрос убирает на
  узких экранах. Единственный фон — волны (`wavy_bg.jpg`) на таблице-обёртке.
- **Насечки-вырезы** по краям карточки (декор с сайта) не делаем: вырез
  показывает то, что под карточкой, а под ней фото — в письме это только
  картинкой на конкретный фон, ломается при любой смене шапки.

## Переменные шаблона

Все со значениями по умолчанию — шаблон рендерится и без данных:

- `$preheader` — скрытый текст превью в списке писем
- `$date` — дата справа сверху, по умолчанию `now()`
- `$slot` / `$body` — HTML тела целиком: приветствие, текст, подпись
  (то, что отдаёт `FormEmailTemplateRenderer`)
- `$legal` — юридический блок футера
- `$links` — `[['label' => …, 'url' => …]]`, по умолчанию ссылка на политику
  с `#` (страниц политики / отписки / помощи в роутах пока нет)
- `$socials` — `[['icon' => …, 'url' => …]]`
