# Nginx: хвосты аудита 26.08.2026

## Задача

Аудит прода 26.08.2026 (HSTS + общие настройки nginx) показал, что сам HSTS
в порядке — правки нужны о другом: утечка версии nginx в 301-ответах,
отсутствующий OCSP stapling и расхождение stage с прод-конфигом по
исполнению PHP.

Продолжение [archived/nginx-hsts.md](../archived/nginx-hsts.md). Работа
только на сервере `89.108.113.198`, в коде приложения не отражается;
референс-копии — [infra/nginx/](../../infra/nginx/).

## Что проверено 26.08 и работает — не переделывать

HSTS `max-age=31536000; includeSubDomains` живьём отдаётся во всех пяти
местах прода (главный блок, `/vendor/livewire/`, `/vendor/filament/`,
`/storage/`, статика) плюс в www-HTTPS-301. Наследование `add_header` нигде
не рвётся — проверено curl'ом по каждому типу ответа, не только по конфигу.

| Проверка | Итог |
| --- | --- |
| `.env` и дотфайлы | 403 |
| Произвольный `.php` в корне | 404 — исполняется только `= /index.php` |
| `.php` внутри `/storage/` | 404 — `^~` отменяет regex |
| TLS | 1.2 + 1.3 живы, 1.0/1.1 отбиты |
| Цепочка сертификата | `Verify return code: 0`, полная до GlobalSign Root R6 |
| catch-all :443 | неизвестный Host отбивается на хендшейке |
| catch-all :80 | 301 на канонический домен |
| `nginx -t` | ok; воркеры перезапущены 26.08 15:09 MSK, работающий конфиг = файлы |
| Референс-копии в `.ai/infra/nginx/` | совпадают с сервером по md5 |

Сертификаты: prod (GlobalSign wildcard) — до **2027-03-06**, stage (LE) —
до **2026-09-26**, `certbot.timer` активен, последний прогон 26.08 12:47.

## Ключевые решения

- **`preload` по-прежнему не добавляем.** Решение из
  [archived/nginx-hsts.md](../archived/nginx-hsts.md) в силе: попадание в
  список необратимо на 6–12 месяцев, `max-age` от него не спасает.
- **Решение «stage трогаем минимально» частично отменяется.** Оно принято
  30.07 из-за Certbot-managed строк, но под него случайно попали и вещи,
  к Certbot отношения не имеющие. Берём только два пункта — ограничение
  exec и `$realpath_root`; `listen`/`ssl_*` от Certbot не трогаем.
- **Короткий `max-age=300` на stage ничего не защищает** — и это новое
  знание, отменяющее обоснование решения «stage max-age не поднимаем».
  Прод отдаёт `includeSubDomains`, `stage.niipigrad.ru` — его поддомен,
  значит у любого браузера, заходившего на прод, stage уже запинён на
  HTTPS на год. Собственный `max-age` стенда на это не влияет никак.
  Сейчас безвредно (LE-сертификат валиден, certbot живой), но комментарий
  в конфиге вводит в заблуждение и его надо переписать.
- **`server_tokens off` поднимаем в `http {}`**, а не дублируем по блокам:
  в `/etc/nginx/nginx.conf` строка уже есть, просто закомментирована.

## Порядок работы

- [ ] 1. **`server_tokens off` → `http {}`** в `/etc/nginx/nginx.conf`
      (раскомментировать). Сейчас директива стоит только в главном
      server-блоке прода, поэтому 301-ответы отдают полную версию:
      `https://niipigrad.ru/` → `server: nginx`, а
      `https://www.niipigrad.ru/` → `server: nginx/1.24.0 (Ubuntu)`.
      Строку из `niipigrad-prod` после этого можно снять как избыточную.
      Проверка: оба ответа и catch-all отдают голое `nginx`.
- [ ] 2. **OCSP stapling на проде** — `ssl_stapling on`,
      `ssl_stapling_verify on`, `ssl_trusted_certificate`, `resolver`.
      Сейчас `OCSP response: no response sent`, клиент с трёхуровневой
      цепочкой GlobalSign ходит за статусом сам — лишний RTT на первом
      соединении. Проверка: `openssl s_client -status` показывает
      `OCSP Response Status: successful`.
- [ ] 3. **stage: привести исполнение PHP к проду.** Заменить
      `location ~ \.php$` на `location = /index.php` (сейчас на stage
      исполняется **любой** `.php`) и `$document_root` на `$realpath_root`
      в `SCRIPT_FILENAME`/`DOCUMENT_ROOT`. Заодно убрать дублирующий
      `include fastcgi_params;` после `snippets/fastcgi-php.conf`
      — безвреден, но мусор.
- [ ] 4. **stage: переписать комментарий про HSTS** под то, что записано
      в «Ключевых решениях» выше. Поднимать ли `max-age` до боевого —
      решить при правке; если поднимаем, добавить HSTS в `/vendor/*` и
      статику stage, как сделано на проде.
- [ ] 5. **Синхронизировать референс-копии** в
      [infra/nginx/](../../infra/nginx/) и сверить md5 с сервером; обновить
      описания в [infra/nginx/README.md](../../infra/nginx/README.md).

## Гочи

- **`add_header` не наследуется** в location со своим `add_header` — если
  шаг 4 поднимет max-age на stage, HSTS придётся дублировать руками во все
  location'ы с собственными заголовками. На проде это уже так и сделано.
- **Certbot-managed строки на stage не трогаем** — `listen`, `ssl_*` и
  весь http-80-блок он перезаписывает при renewal.
- **`ssl_trusted_certificate` для stapling** — в `_.niipigrad.ru.crt` лежат
  все три сертификата (leaf + intermediate + root), отдельный chain-файл
  готовить не нужно, можно указать на него же.
- **`resolver` для stapling** — в системе `127.0.0.53` (stub
  systemd-resolved). Нужен `valid=`; если stub окажется капризным, вписать
  публичный резолвер вторым.
- **Порядок раскатки** (из [infra/nginx/README.md](../../infra/nginx/README.md)):
  бэкап в `/root/backup/`, `nginx -t`, только потом `systemctl reload nginx`.
  Сервер и референс-копию правим вместе, иначе копия протухнет.
- **`zz-` в имени catch-all обязателен** — файл должен грузиться после
  `niipigrad-prod` из-за `ipv6only` в первом объявлении адреса.

## Границы

- **CSP и `Permissions-Policy` — не в этот заход.** Их нет ни на проде, ни
  на stage. Для Filament придётся подбирать политику под инлайн-скрипты
  Livewire/Alpine — это отдельная работа с риском поломать админку, а не
  строчка в конфиг.
- **`http2 on;` — не сейчас.** На nginx 1.24 текущий синтаксис
  `listen … http2` корректен; менять при апгрейде на 1.25+, где он
  становится deprecated.
- **`worker_connections 768`** — дефолт Ubuntu, для нынешнего трафика
  хватает. Не трогаем.
- **brotli** — не ставим, gzip настроен и работает.
