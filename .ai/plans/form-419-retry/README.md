# 419 на публичной форме: повтор запроса с новым токеном

План фикса к багу **#44** ([bugs.md](../bugs.md)): посетитель отправляет форму
из вкладки, провисевшей дольше двух часов, и получает 419 — Livewire
показывает англоязычный `confirm("This page has expired…")` и перезагружает
страницу, введённое пропадает.

## Ключевое решение

`SESSION_LIFETIME=120` **оставляем**. Короткая сессия ценна для админки
(забытая вкладка, уведённая кука протухают), а у гостя в сессии лежит только
CSRF-токен — его протухание ни от чего не защищает, но стоит заявки. Чиним не
срок жизни, а потерю данных.

Таймер идёт с момента **открытия вкладки**, а не с начала заполнения: типичный
случай — страницу открыли утром, заполнили вечером за две минуты. Данные
свежие, устарел только токен.

## Почему повтор вообще возможен

- **Снапшот переживает новую сессию.** Подпись — HMAC на ключе приложения:
  `Checksum::generate()` берёт `app('encrypter')->getKey()`
  (`vendor/livewire/livewire/src/Mechanisms/HandleComponents/Checksum.php:22-35`).
  К сессии он не привязан, поэтому после выдачи новой сессии тот же снапшот
  принимается.
- **Токен читается на каждый запрос.** `getCsrfToken()` в `dist/livewire.js`
  каждый раз смотрит `meta[name="csrf-token"]`, и токен уходит в теле
  (`_token`), не в заголовке. Достаточно переписать содержимое меты —
  следующий запрос уйдёт с новым токеном.
- **`preventDefault()` гасит дефолт.** В `dist/livewire.js` порядок такой:
  `fail({status, content, preventDefault}); if (preventDefault) return;` и
  только потом `handlePageExpiry()` с `confirm`. То есть перехват снимает и
  англоязычный диалог, и модалку ошибки.
- **Дубля заявки нет:** первый запрос отбивается CSRF-мидлварой до того, как
  дело доходит до компонента.

## Что делаем

### Backend

1. **NEW** `app/Http/Controllers/CsrfTokenController.php` — инвокабельный,
   отдаёт `{"token": "…"}` с `Cache-Control: no-store`.
2. **EDIT** `routes/web.php` — `Route::get('/csrf-token', ...)` с
   `throttle:60,1`, обязательно **выше** catch-all `Route::get('/{slug}')`
   (`routes/web.php:28`), иначе роут перехватит страница. Группа `web`, гостю
   доступен: протухшая сессия заменяется новой, свежая кука приезжает тем же
   ответом.
3. **NEW** `tests/Feature/Http/CsrfTokenTest.php` — гость получает 200 и
   непустой токен, заголовок `no-store`, catch-all не перехватывает.

### Frontend

4. **EDIT** `resources/js/app.js` — `Livewire.hook('request', ({ payload, fail }) => …)`,
   внутри `fail(async ({ status, preventDefault }) => …)`:
   - только `status === 419`;
   - только если в payload есть компонент `forms.public-form` (имя лежит в
     `memo.name` снапшота) — в админке оставляем штатное поведение, чтобы не
     продлевать молча сессию администратора;
   - `preventDefault()`;
   - `fetch('/csrf-token')` → записать токен в `meta[name="csrf-token"]`
     (`resources/views/layout/base.blade.php:6`);
   - повторить ровно те вызовы, что были в payload: по каждому компоненту
     `Livewire.find(memo.id).$wire.call(method, ...params)`;
   - повтор строго один, по флагу; если и он упал — показать по-русски
     «Страница была открыта слишком долго. Обновите её и отправьте форму
     заново».

### Проверка

5. На stage с `SESSION_LIFETIME=1`: открыть форму, подождать пару минут,
   отправить — заявка уходит без перезагрузки. JS в проекте автотестами не
   покрыт, только руками.
6. Пересборка ассетов — на владельце.

## Границы

- `SESSION_LIFETIME` не трогаем — вариант «поднять» отброшен осознанно.
- Админку не трогаем: перехват ограничен публичной формой.
- Honeypot и RateLimiter в `SubmitFormAction` не затрагиваются.

## Отброшенные варианты

- **Ничего не делать** — посетитель видит английский системный диалог и пустую
  форму, уходит без объяснений (живой случай 28.08 в #44).
- **Только сообщение** вместо повтора — дешевле, но человек всё равно
  перезаполняет форму.
- **Поднять `SESSION_LIFETIME`** — лечит симптом ценой длинной сессии админки.
- **Разводить lifetime для гостей и админов** — Laravel так не умеет, самодельное
  продление куки добавляет больше механики, чем экономит.
