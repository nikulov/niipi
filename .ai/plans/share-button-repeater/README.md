# Репитер соцсетей в блоке «Поделиться + кнопка»

## Задача

Набор кнопок шаринга перестаёт быть зашитым в шаблон: в схеме блока
`share-button` появляется репитер «SVG + ссылка», фронт рендерит полоску
циклом по этому массиву.

Отменяет решение «в админке ничего не настраивается» из
[archived/share-button.md](../archived/share-button.md).

## Ключевые решения

- **В поле ссылки — шаблон с `{url}` / `{title}`**, а не готовый адрес.
  Alpine-хелпер `share()` остаётся: он подставляет `location.href` и
  `document.title`, поэтому блок по-прежнему шарит ту страницу, на которой
  стоит. Это ровно та проблема, из-за которой репитер отвергли в первый раз.
- **Поле ссылки — обычный `TextInput`, не `UrlInput`.** У `UrlInput` есть
  suffix-action «открыть страницу», на шаблоне с `{url}` она даёт битую ссылку.
- **Пустой репитер — полоски нет вообще**, рендерится только основная кнопка.
  Следствие: у всех уже опубликованных Post/Project шаринг пропадёт — в их
  сохранённом JSON ключа `socials` нет. Вернётся там, где редактор заполнит
  репитер.
- **Кнопка «Копировать ссылку» — не элемент репитера**, а `Toggle showCopy`
  в схеме блока (default `true`): это JS-действие (`navigator.clipboard`),
  в пару «SVG + ссылка» оно не ложится.
- **Дефолтный набор — те же ВК / Telegram / MAX**, что были зашиты, плюс
  включённое копирование. Живёт одним массивом в `ShareButton::defaultSocials()`
  и оттуда же попадает в `getDefaultBlock()`.
- **Дефолтные иконки — на public-диске**, `images/icon/{vk,telegram,max}.svg`
  (`ShareButton::defaultSocials()`). Только этот корень видят оба потребителя:
  `FileUpload` рисует превью в админке, `inline_svg()` инлайнит на фронте.
  Копия тех же файлов лежит в git в `public/images/icon/` — оттуда их заливают
  на новый стенд, сам `public/` ни одному из двух не виден.

## Гочи

- `BaseFileUpload:112` — Filament при гидрации формы **выкидывает из состояния
  пути, которых нет на диске** (`getDisk()->exists()`). Поэтому дефолт репитера
  заработает только после того, как файлы реально лягут в `images/icon/`
  на public-диск; до этого момента иконки в новом блоке будут пустыми.
- `/resources/images/` — в `.gitignore` (строка 25). Новые статические SVG туда
  класть нельзя, они не уедут в релиз. И осторожно: `inline_svg()` резолвит
  `resource_path()` **первым**, так что случайная копия в `resources/images/`
  локально перебивает файл с диска, а на проде её нет — расхождение молчит.
- Дефолт репитера и то, что лежит в БД, — **разной формы**: `->default()`
  требует `iconUrl` массивом (raw state загрузки), сохранённый блок держит
  строку. Отсюда пара `defaultSocials()` / `defaultSocialsAsFormState()`,
  подробности — в `conventions.md`, раздел «Пути к файлам».
- Post/Page/Project — `TracksMediaUsage`, пути внутри JSON блоков вытаскиваются
  рекурсивно. Загруженные в репитер SVG становятся «используемыми» сами,
  отдельной работы не требуется.

## Границы

Счётчиков репостов, OG-разметки и Web Share API не делали. Блок `button`
остался без шаринга. Иконка `icon-share` (триггер) и `icon-link` (копирование)
остаются зашитыми — они не часть настраиваемого набора.
